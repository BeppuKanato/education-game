# 論拠 — 学習ディベートゲーム

発言の矛盾を、根拠で撃ち抜く。研究室を舞台に、会話・資料確認・矛盾指摘を繰り返して結論にたどり着く、ブラウザ向け1人用ゲームです。

収録シナリオは **「そのアプリ、本当に効果あり？」**。比較条件、アンケートの分母、未確認と無効の違いという3つの論点を扱います。人物・会話・実験データは架空です。

## 動かす

Node.js 24 LTSを推奨します（22.12以上）。

```bash
npm ci
npm run dev
```

表示されたURLをブラウザで開きます。16:9の画面をウィンドウに合わせて拡縮します。研究室のPCでは横長モニター＋全画面がおすすめです。

```bash
npm run build      # 型チェック → ドメイン・Presenterテスト → 本番ビルド
npm run preview    # 本番ビルドをローカルで確認
```

## 操作

| 操作 | キーボード・マウス | 標準ゲームパッド |
| --- | --- | --- |
| 決定・台詞送り・発射 | Enter / Space / 画面クリック | A / 下側ボタン |
| 照準移動 | マウス / 方向キー / WASD | 左スティック / 方向キー |
| 弾丸切替 | Q / E / 画面の ‹ › | LB / RB |
| 資料確認 | X / 資料ボタン | X / 左側ボタン |
| 資料の選択 | 方向キー / 一覧クリック | 方向キー / 左スティック |
| 戻る | Esc / Backspace | B / 右側ボタン |
| 一時停止 | P / Esc | Y / 上側ボタン / Start |
| 全画面・解除 | F / 右上ボタン | 右上ボタンをマウスで操作 |
| 効果音切替 | M / ♪ボタン | メニューから操作 |

ボタン表記はXbox型です。他のコントローラーは物理的な位置で対応します。ブラウザがゲームパッドを認識するには、接続後にボタンを一度押す必要があります。特殊な非標準マッピングの機種ではキーボード・マウスを使ってください。

会話の文字送り中の決定は全文表示、全文表示後の決定は次の台詞です。議論の発言は繰り返し再生されます。色のついた指摘箇所が、すべて間違いとは限りません。発言と弾丸の組み合わせで判定します。資料や結果を表示している間は議論を停止します。

進行はブラウザのlocalStorageへ自動保存します。「続きから」で再開できます。別の端末やブラウザへの同期はありません。保存を許可しない環境でも、セーブ以外の機能は遊べます。

## Cloudflareに接続する

**Workers Static Assets / Workers Builds** 向けの `wrangler.jsonc` を同梱しています。サーバー処理・DB・APIキー・有料APIは不要です。ブラウザがゲーム本体、Phaser、素材を読み込んで実行します。

Cloudflareの **Workers & Pages → Create application → GitHub** からこのリポジトリを選び、次を設定します。

| 設定 | 値 |
| --- | --- |
| Worker名 | `education-game` |
| 本番ブランチ | `main` |
| ルートディレクトリ | リポジトリのルート |
| Build command | `npm run build` |
| Deploy command | `npm run deploy` |
| Node.js | 24（必要ならビルド変数 `NODE_VERSION=24`） |

Worker名は `wrangler.jsonc` の `name` と一致させてください。別名を使う場合は両方変更します。依存関係のインストールはCloudflareのビルド環境で実施されます。初回のSave and Deployが成功すると、発行された `workers.dev` URLを開いて遊べます。その後はmainへのpushで型チェック・テスト・ビルド・配信が実行されます。GitHub Actionsのデプロイワークフローを別途作る必要はありません。

CLIで配信する場合は、Cloudflareに認証した環境で `npm run build` → `npm run deploy` を実行してください。CloudflareアカウントやGitHub接続そのものは、このリポジトリのコードからは設定しません。

## シナリオを編集する

`src/content/scenario.json` に人物、資料、会話、指摘箇所、正解の組み合わせ、指摘後の解説、結論を定義しています。会話パートと矛盾指摘パートを配列の順序で組み合わせます。

- `conversation.lines`：発言者と台詞。`grantEvidence` で、その台詞へ到達した際に弾丸を追加。
- `debate.lines`：発言を `prefix`・`target`・`suffix` に分ける。`target` が狙える文字。
- `debate.solutions`：指摘箇所IDと、成立する弾丸IDの組み合わせ。別解は複数登録。
- `evidence`：資料の出典名・短い説明・本文。
- `revision`：既存セーブと両立しない構造変更時に増やす。互換性のないセーブは「続きから」の対象外になる。

起動時にZodと参照整合性チェックで、存在しないID、重複ID、解く前に取得できない正解弾丸などを検出します。

E2Eでは実際に起動し、誤った指摘・資料確認・停止・3つの指摘・成功後の再読み込み・結論・再プレイを確認します。開発時限定の読み取り専用 `window.__educationGame` は診断用で、本番ビルドには含まれません。

背景・キャラクターはオリジナルの生成画像です。効果音はWeb Audioで合成しています。ボイス・BGMは含めていません。既存作品の素材は使用していません。
